Augur is a source-first design system. The near-term external consumption path is the generated, shadcn-compatible source registry; applications inside this repository may consume the workspace package directly.

## Choose a consumption path

### Source registry

The repository publishes generated registry items under `/r/`, including the base theme and current components/patterns. Registry items are generated from canonical package sources rather than maintained as parallel copies.

Start with the `augur-theme` item, then add the components or patterns your application needs. Pin a verified repository ref for reproducible consumption rather than treating `main` as a release channel.

Once you have the resolved URL for a registry item, install it with the standard shadcn source-install command:

```sh
npx shadcn@latest add "$REGISTRY_ITEM_URL"
```

The URL should point at the generated item you intend to consume; the design-system repository remains the authority for which items and refs are valid.

### Workspace package

Applications in this workspace can import from `@augur/design-system` directly.

```tsx
import { Button, Card, Input } from "@augur/design-system";
import "@augur/design-system/styles.css";
```

The aggregated stylesheet delivers self-hosted fonts, generated tokens, semantic light/dark roles, typography roles, shared focus behavior, and the system's structural styling.

## Theme behavior

Light and dark are equal everyday themes. With no explicit theme, the system preference governs. Pin a theme with `data-theme="light"` or `data-theme="dark"` on the document or a subtree.

See [Theming](/foundations/theming) for the selection and scoping contract.

## Start with decisions, not components

Before composing a page, use the foundations to understand Augur's hierarchy and interaction language:

- [Typography](/foundations/fonts)
- [Color](/foundations/color)
- [Layout and geometry](/foundations/layout-geometry)
- [Interaction](/foundations/interaction)
- [Theming](/foundations/theming)

Then choose components and patterns by their documented `When to use` / `When not to use` guidance rather than by visual resemblance.

## Current starter set

The current documented starter set includes Button, Card, Input, Dialog, FormField, PageHeader, and EmptyState. Reference Record remains a source-grounded composition under review as either a reusable pattern or a retained reference specimen.

## Sources of truth

`DESIGN.md` owns adopted design values representable by the pinned schema. Generated token outputs are derived artifacts. Foundation documentation owns maintained design guidance that does not fit the schema cleanly, while component and pattern pages own usage and composition decisions.

For package/export details, see [Package entries](/reference/package-entries). For contribution rules and verification, see [Contributing](/reference/contributing).
