## Authority and acceptance

The maintainer delegated exact visual choices for this run to the Astra visual
director. The [issue 42 authority record](https://github.com/jubalm/augur-design-system/issues/42#issuecomment-5556190059)
records that delegation. This contract adopts the implementation direction on
2026-09-06; **final human visual acceptance remains pending in
[issue 53](https://github.com/jubalm/augur-design-system/issues/53)**. Adoption here
allows the explicitly assigned downstream work to use one coherent direction.
It does not claim that the maintainer has personally inspected these frames,
that the package has changed, or that a release is approved.

`ARCHITECTURE.md` retains technical authority. `DESIGN.md` remains canonical for
adopted values representable by its pinned schema. The representable values
below were encoded in `DESIGN.md` and regenerated into the token artifacts on
2026-09-06 (issue 45), so runtime consumers now read the encoded foundations.
Concepts outside that schema remain in maintained foundation documentation and
component code.

## The selected composition contract

A frame is the maximum content width, including its internal columns. It is
`min(1400px, viewport width minus two outer gutters)`. At widths of 960px and
above, gutters are 64px and section gaps are 80px. Below 960px, gutters are 24px
and section gaps are 48px. At 1440px the centered 1400px frame therefore has 20px
actual side margins; 64px is the minimum gutter, not an instruction to stretch
the frame. Reading paragraphs use a maximum measure of 65ch.

Local grid gaps are 32px at 960px and above and 24px below. The opening footer retains a 32px column gap on tablet and uses 24px when stacked on mobile. The local spacing
scale is 4, 8, 12, 16, 24, 32px, with 48, 64, 80px as composition roles rather
than arbitrary extra component padding. The compact choice gap is 24px desktop
and 16px below 600px. Record field and panel padding are 24px, becoming 16px below
600px. Opening message gaps are 32px in both modes.

| Frame | Desktop at 960px and above | Tablet at 600–959px | Mobile below 600px |
| --- | --- | --- | --- |
| A — Brand opening | Rail/message columns 1:2 with 32px gap. Message contains title, signal, support, then text action. Footer spans both columns in three equal tracks. Opening top inset 48px; minimum composition height 520px. | Rail/message remain 1:2 with 24px gap; footer remains three tracks. Natural height replaces the desktop minimum. | Rail, message, then the three footer entries stack in DOM order. Remove the rail's repeated sentence; keep its label and source note. No fixed height or top inset. |
| B — Editorial specimen | Primary specimen/support columns 2:1. Main column: display field, editorial section specimen, component heading specimen. Support: three rule-led explanations. | Main specimen first; three supporting explanations follow in equal columns. Support headings use 20/26 regular to fit the narrower tracks. | Everything stacks: display, editorial section, component heading, then the three explanations. Preserve 40/44 display size; wrap the deliberate sentence lines naturally. |
| C — Compact record | Record/support columns 2:1. Record leads with state rail and question, then two equal choices, then status/response/time. | Record first, explanation below; retain two equal choices. | Same order. Keep choices side by side; allow question and response values to wrap, never clip. Labels remain left and values right. |

Theme changes only colors. Content order, typography, dimensions, wrapping rules,
focus geometry, and interactive behavior remain equal. The reference's top review
controls and bottom adoption note are evidence furniture, not a proposed docs hero.

Size creates order; weight confirms it. Do not globally lower heading weights.
Use sentence case except short metadata labels. Do not stack large size, 600
weight, uppercase, and green for the same headline. Supporting prose stays
Schibsted Grotesk; font alternation is never decoration.

## Shape, control, and interaction decisions

Panels, specimen fields, Card, Dialog, Button, Input, and triggers use **0px
radius**. The old 8px surface / 6px control proposal and its subtraction rule are
rejected. The fixture shows the 6px control beside the selected 0px control once.
That comparison is decision evidence, not a supported runtime variant.

Official artwork remains untouched. A supplied circular REP icon keeps its
circular geometry; a circle intrinsic to a radio control may remain circular
when needed to communicate its interaction. Neither is a general pill or rounded
panel exception. No new rounded brand container or redrawn identity is authorized.
The maintainer-approved interim replacement — the text identity — is
specified in [Brand identity](/foundations/identity).

Retain desktop control heights 32px small, 36px default, and 40px large, and
16px inline / 20px standalone icons. On a coarse pointer, actionable targets are
at least 44px high and wide; text controls may be wider. The fixture previews the
default size and raises it to 44px under `pointer: coarse`. This policy does not
make noninteractive labels pretend to be controls.

Keyboard focus uses a 2px solid ring with a 2px offset: Deep on light, Green on
dark. Use `:focus-visible` and preserve browser heuristics; do not suppress focus
on text inputs merely because a pointer initiated it. Keep focus clear of clipped
containers. The explicit label and normal interaction affordance remain visible.

Adopt immediate state feedback with **no decorative motion**. New controls and
Dialog transitions default to 0ms. Reject the unreviewed universal 150/250ms
proposal; a future functional animation requires a specific reason and review.
Reduced motion must remove transforms, loops, and smooth scrolling; retained
legacy durations collapse to at most 0.01ms during migration.

Name record states Open, Closed, Pending, and Final. Hover uses an existing
neutral surface step; pressed or selected choices may use a strong neutral
inversion plus `aria-pressed` and an explicit response label. Disabled controls
remain labeled and noninteractive; do not rely solely on opacity. Loading keeps
width stable, exposes `aria-busy`, and states what is happening. No new state color
palette or green success dot is introduced.

## Signal and border hierarchy

The baseline orienting signal is **32px wide and 2px high**, with no radius.
It marks the start of the principal message or a record's state rail. Use Deep
on light and Green on dark through the existing primary semantic relationship.
Choose one main signal per coherent task area: this rule **or** a primary action.
Keyboard focus and official artwork are justified additional green instances.
Do not add a stripe to every card or every section, and never stretch this rule
across the frame. B has no green rule because its specimen hierarchy already
supplies the priority. A's text action stays neutral.

| Relationship | Light | Dark | Meaning |
| --- | --- | --- | --- |
| Editorial separator | Border, 1px | Surface 3 / Raised, 1px | Quiet grouping reinforced by headings, alignment, and spacing; not an interactive boundary. This dark relationship is new and fixture-local pending issue 45 migration. |
| Control edge | Graphite, 1px | Mist, 1px | Perceivable boundary against the adjacent canvas, panel, and neutral control fill. Distinct from the editorial separator. |
| Record field / panel | Muted / White | Surface 1 / Surface 2 | Tonal grouping, square geometry, no shadow; panel separator may remain quiet because text/order also define the record. |
| Focus / short signal | Deep | Green | High-contrast attention cue; focus adds its 2px offset and never replaces the label. |

These relationships reference existing generated color values; no new raw color,
opacity trick, charcoal palette, shadow, gradient, or glow is permitted. Quiet
rules do not need to imply a control; meaningful control edges must clear 3:1
against adjacent fills. Text must clear 4.5:1, including secondary metadata.
The fixture evidence records recomputed pairings and the actual rendered colors.

## Good and poor translations

| Do | Don't | Source and consequence |
| --- | --- | --- |
| Compose whitespace around a message and a deliberate rail | Leave a huge empty side area caused by a generic narrow content column | Pages 1/3: negative space belongs to the composition; the 1400px frame and 1:2 opening make its structure explicit. |
| Use open columns and quiet rules for editorial explanation | Put every paragraph in a rounded card | Pages 5/18/22: alignment and hierarchy carry the page, with fields reserved for actual specimens. |
| Lead with a concise identity message | Turn installation state, build status, or package internals into the hero | Pages 1/25: the opening explains purpose. Technical information belongs in reference sections. |
| Show the actual question, choices, state, and response | Replace a record with a generic explanatory card | Pages 20/23/25: the reader can inspect the record rather than read about it. |
| Keep the display specimen 600 and editorial titles 400 | Make every heading semibold or every heading regular | Pages 22/23: each type role has a job; use the table above. |
| Use Deep for a meaningful light-surface signal | Copy bright Green from a printed light example without contrast review | Page 20 plus current DESIGN.md: the web translation honors accessibility and source intent. |
| Reserve stronger edges for controls | Draw a bright Mist grid around all dark editorial content | Pages 18/20/25: surfaces and hairlines organize; controls remain perceivable. |

## Review and reproduction

Run the fixture command documented in its README to reproduce light and dark at
1440×1000, 768×1024, and 390×844. Inspect each full-page capture alongside its
named PDF sources. Check focal point, shared left edges, role weights, surface
hierarchy, signal purpose, and the intentional stacking changes described above.
The evidence includes a focus close-up and a verification report recording font
files, computed family/weight/size/line-height, font readiness, zero failed local
requests, keyboard behavior, theme geometry parity, overflow, and contrast.

The shared MDX source produces `/foundations/visual-direction` and its clean
Markdown equivalent `/foundations/visual-direction.md` through the existing
pipeline. Durable source images and screenshots are retained with the fixture;
no `/tmp` path is required for the handoff. Captures establish what was rendered;
the annotated comparisons and explicit acceptance gate establish what has and
has not been accepted.
