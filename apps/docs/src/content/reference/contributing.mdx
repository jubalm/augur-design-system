This page summarizes how the repository is meant to be worked in. It is
a convenience view; the canonical documents are
[`AGENTS.md`](https://github.com/jubalm/augur-design-system/blob/main/AGENTS.md)
(execution and handoff rules),
[`ARCHITECTURE.md`](https://github.com/jubalm/augur-design-system/blob/main/ARCHITECTURE.md)
(structure, boundaries, distribution), and
[`README.md`](https://github.com/jubalm/augur-design-system/blob/main/README.md)
(commands and current status). Where this page and a canonical document
disagree, the canonical document governs.

## Source authority

Design decisions have a strict precedence, so an agent never has to
guess whether an older artifact overrides the maintained system:

| Rank | Source | Governs |
| --- | --- | --- |
| 1 | `DESIGN.md` (repository root) | Adopted design values representable by the pinned `@google/design.md` schema, plus maintained brand guidance |
| 2 | Generated tokens and theme output | Build artifacts derived from `DESIGN.md` — never edited as independent sources |
| 3 | Foundation documentation and component implementation | Concepts the schema cannot represent: spacing, sizing, radius, focus, motion, state semantics |
| — | `resources/brand/augur-brand-foundation.pdf` | Upstream reference; informs the system, never silently overrides maintained decisions |
| — | Open proposals | Carried in the [decision record](/foundations/decisions) with explicit review status; no authority until adopted |

Working rules that follow from this order: prefer semantic tokens over
hard-coded values; do not duplicate raw `DESIGN.md` values in theme
maps, docs examples, or registry copies; do not import artifacts from
the earlier OpenDesign repository as current authority; record material
design decisions with rationale and source.

## Supplied artwork

The brand PDF informs the system; the production identity artwork is
not silently redrawable:

- Preserve the supplied logo lockups, glyph, and REP token icon: never
  redraw, recolor, rotate, distort, crop, stretch, or simplify them.
- Respect the clearspace unit (one lowercase **a** of the wordmark on
  all sides) and the minimum sizes: glyph 50px high, horizontal lockup
  150 × 50px, vertical lockup 94 × 93px.
- Choose variants from the background first: two-tint Color on light
  surfaces, two-tint Reversed on dark; single-tint only for constrained
  supporting placements.
- Production masters for the logo family are **not in this repository**
  (held upstream; recorded with the text-identity interim rule in
  [`resources/brand/PROVENANCE.md`](https://github.com/jubalm/augur-design-system/blob/main/resources/brand/PROVENANCE.md)).
  Missing masters are a documented dependency, not permission to redraw.

## Dependency layering

Conceptual layers flow one way:

```text
Foundations → Tokens → Primitives → Components → Patterns → Products
```

Enforced boundaries in this workspace:

- `packages/design-system` (`@augur/design-system`) is the only
  component package; `apps/docs` is plain Astro documentation.
- The docs app may import the package (`workspace:*`); the package must
  never import docs code or docs-only dependencies.
- Tokens know nothing about components; components reference semantic
  roles, never raw values; the design system knows nothing about
  product-specific features.
- Product workflows stay outside this repository. npm publication,
  Storybook, and package extraction each need concrete requirements
  before they exist.
- The future registry path stays independent of the npm package:
  registry-installed source never imports `@augur/design-system`.

## Checks

Deterministic checks are the blocking validation layer; AI design
review is advisory. Run what applies to your change from the repository
root:

| Command | Proves |
| --- | --- |
| `bun install --frozen-lockfile` | The committed lockfile and manifests agree (CI's install). |
| `bun run lint` | `DESIGN.md` validates against the pinned `@google/design.md` 0.4.0 schema. |
| `bun run lint:code` | TypeScript/TSX passes oxlint (typescript, react, jsx-a11y). |
| `bun run typecheck` | `tsc --noEmit` over package sources, workspace tooling, and the test harness. |
| `bun run check:workspace` | Workspace boundaries load: package entry, `./styles.css` export, docs resolution. |
| `bun run test` | Vitest + Testing Library + axe suite against the real package. |
| `bun run --cwd packages/design-system tokens:check` | Regenerated tokens are byte-identical to committed artifacts. |
| `bun run --cwd packages/design-system tokens:verify-failures` | Controlled token-generation failure paths exit nonzero and write nothing. |
| `bun run --cwd apps/docs check` | `astro check` diagnostics for the docs app (0 errors). |
| `bun run --cwd apps/docs build` | Static docs build; build with `DOCS_BASE_PATH=/augur-design-system` for the repository-subpath mode. |
| `bun apps/docs/fixtures/verify-docs.mjs` | Built site in headless Chromium: fonts, theme contract, keyboard, actions. |
| `bun apps/docs/fixtures/verify-markdown.mjs` | Clean-Markdown inventory, parity, links, and `llms.txt` in both base modes. |
| `bun apps/docs/fixtures/verify-content-failures.mjs` | Invalid metadata and missing component sections fail the build clearly. |

CI runs the first eight on every pull request and push to `main`.
Browser coverage is not in CI yet (tracked for issue #15), so the docs
fixtures are run locally per change. There is deliberately no `build`
command for the package yet (tsup deferred).

## Workflow

1. Read the issue and its dependencies; record intended scope and
   branch in the issue before editing. Branches are
   `issue-<number>-<short-description>`; check for an active owner or PR.
2. Implement the issue's acceptance criteria and exclusions — no
   absorbed prerequisites or adjacent issues.
3. Verify with the checks above; for visual changes, inspect real
   rendered examples in **both themes** and relevant viewport sizes,
   including keyboard and focus behavior.
4. Open a PR linked with `Closes #<number>`, including outcome, changed
   surfaces, commands with observed results, and remaining limitations.
5. Leave a handoff in the issue or PR: branch/commit, completed
   criteria with evidence, remaining work, blockers and decisions.

Merge, release publication, public deployment, DNS, licensing, and
repository transfer are explicit maintainer actions; a prepared PR is
not a merged change, and issues are not closed on implementation claims
alone.
