Reference Record is a **reference composition**, not a default product workflow. It demonstrates how Augur handles a dense record when state, question, equal choices, response, and timing metadata must remain legible together.

Use it as evidence for record-language decisions. Do not copy its fixture content or submission semantics into a product unless a product-specific pattern has been designed for that workflow.

## What it demonstrates

- explicit state before color;
- the question as the first substantive focal point;
- two choices with equal visual structure when neither should outrank the other;
- response and timing metadata kept quiet but readable;
- one short orientation signal rather than repeated accent decoration;
- identical content order and geometry across light and dark themes.

## The record, rendered live

## When this reference is useful

Consult it when designing read-only review/history records or when checking whether a new record composition preserves question priority, state clarity, equal choice treatment, and quiet metadata.

For page-level wayfinding and operations, use [PageHeader](/patterns/page-header). For a live voting/submission workflow, define a product pattern rather than treating this reference specimen as an interactive contract.

## Accessibility

State and response are real text. The short signal is decorative. Static choices remain real Buttons but are explicitly unavailable and do not announce a fabricated selection.

Contrast and focus behavior come from the maintained package roles and shared interaction contract.

## Provenance

This composition is retained from the source-grounded record review because it provides useful evidence for Augur's dense-record language. The detailed historical comparison remains in repository fixtures; current design decisions live in the maintained foundations.
